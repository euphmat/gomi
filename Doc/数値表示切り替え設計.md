# 数値表示切り替え設計

## 目的

ゲーム内の数量を、表示幅に強い省略表記（`10k`）と、読み取りやすい桁区切り表記（`10,000`）で切り替えられるようにする。表示設定は計算値やセーブデータに影響させない。

## 設計方針

- 表示の唯一の入口を `js/utils/format.js` の `formatNumber()` にする。
- 初期値は従来と同じ省略表記とし、既存 UI の幅を増やさない。
- 設定は端末固有の UI 設定として `localStorage.numberNotation` に `compact` / `full` を保存する。クラウドセーブには混ぜない。
- 省略表記は3桁ごとの短縮単位を uncentillion まで生成し、有限な JavaScript `Number` の全範囲を扱う。それを超える `BigInt` は表示長が増えない指数表記へフォールバックする。
- 有効数字は最大3桁とし、丸めによって `1000k` にならないよう次の単位へ繰り上げる。
- 桁区切り表記は `Intl.NumberFormat('ja-JP')` をキャッシュして利用する。
- `NaN` / `Infinity` は UI へ流出させず `0` と表示し、負数と `BigInt` も扱う。

## UI と再描画

- 設定画面の「ゲームプレイ」に、現在の見た目を例示した2択コントロールを置く。
- 切り替え時にルート要素へ `data-number-notation` を反映し、`numberNotationChanged` を通知する。
- 通常画面は現在ルートを再描画する。戦闘画面は進行を破棄せず、保持中の BattleManager が HUD とタブだけを再描画する。
- ヘッダーの Gold / Prism は可変幅・省略表示を許可し、長い桁区切り値でも設定・更新・クエストボタンを押し出さない。完全な値は `title` と `aria-label` でも参照できるようにする。
- 数値列では `tabular-nums`、狭いカードでは `min-width: 0` と `text-overflow: ellipsis` を使い、横方向のレイアウト破壊を防ぐ。

## 移行範囲

- 既存の `formatNumber()` 呼び出しは自動的に新設定へ追従する。
- 個別の `toLocaleString()`、戦闘統計、鉱山の数量表示、ロック画面などの独自処理を共通フォーマッターへ移行する。
- 日時、割合、時刻、入力欄の生値など「数量表記の切り替え対象ではない値」は変更しない。

## 検証

- 境界値（999 / 1000、丸め繰り上げ、負数、小数、巨大数、`Number.MAX_VALUE`、`BigInt`）を単体テストする。
- 設定の既定値・保存・イベント通知をテストする。
- 直接の数量用 `toLocaleString()` が残っていないことを静的検索で確認する。
- ローカルブラウザ試験は禁止されているため、ブラウザを起動する E2E / visual test は行わず、モジュールテスト・構文検査・コード上のレスポンシブ制約で確認する。
